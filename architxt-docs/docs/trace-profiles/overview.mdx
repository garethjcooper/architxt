# Trace profiles

A **trace profile** tells architxt how to turn a raw log or trace file into structured records and — when sequence mining is enabled — a mined sequence analysis document. Once produced, the trace document keeps going through the normal architxt pipeline: entity detection, mental models, Reflect, and contextual graph sync, without architxt becoming a full observability backend.

## Where trace profiles apply

Trace profiles are used in three places:

1. **Trace document upload** — when you upload a file with **Trace upload** enabled, you can pick a profile. The profile name is stored in the document's processing options and applied during extraction.
2. **Document management** — the documents list shows each document's **Type** (`Document` or `Trace`) and, for trace documents, its **Trace Profile**. The **Document Details** dialog and the multi-select **Config** bulk action let you change the profile on existing trace documents.
3. **The Trace Profiles page** — where you create, edit, version, and test profiles against sample data without uploading a full document.

A profile is not tied to a single file. Any number of trace documents can reference the same profile, and the profile is resolved at extraction time, so editing a profile affects the next extraction run. Changing a trace document's profile warns that re-extraction may invalidate existing extracted data.
